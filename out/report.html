A.2 Recovered homographies

computeH(im1_pts, im2_pts) builds the linear system below from the clicked correspondences and solves it by least squares. A point (x,y) in image 1 maps to (x',y') in image 2 with

x' = (a x + b y + c) / (g x + h y + 1)
y' = (d x + e y + f) / (g x + h y + 1)

=>  [ x  y  1  0  0  0  -x x'  -y x' ] h = x'
    [ 0  0  0  x  y  1  -x y'  -y y' ] h = y'      h = [a b c d e f g h]^T

Each correspondence adds two rows to A (n points: A is 2n x 8).

A.3 Warping and rectification

Both warps use inverse warping: for each output pixel apply H-1 to find where it came from in the source and sample there (no holes). Nearest neighbour rounds to the closest source pixel; bilinear blends the 4 surrounding pixels. Pixels with no source data get alpha = 0.

Errors are in 0-255 pixel units. NN vs bilinear is how much the two warps disagree. Rotate-and-back rotates the whole image by 7.3° with each method and back again, then compares with the original (the only ground truth available), so it measures how much each interpolation damages the image on its own. A lower number is not automatically better-looking: nearest-neighbour often recovers most pixels EXACTLY (small mean error) but makes large errors on edges (jaggies, half-pixel shifts), while bilinear changes every pixel slightly (blur, applied twice in a round trip) so its RMSE can be higher even though it looks smoother. Compare the numbers with the zoomed images. Full numbers are in each rectification's text file.

Speed vs quality

Bilinear took about 3.2x as long as nearest neighbour (4 reads and ~10 multiply-adds per channel instead of 1 read). In exchange it removes blocky staircase edges and pixel-doubling when the warp enlarges the image (zoom panels), at the cost of slight blur. When the warp shrinks the image both can alias, since neither averages over a footprint.

A.4 Mosaics

Procedure. (1) Recover H between each neighbouring pair from the clicked points. (2) Chain them (products / inverses) so every image maps into the frame of the middle image, which stays unwarped. (3) Push each image's corners through its H to get the mosaic's bounding box. (4) Inverse-warp every image (bilinear) into that canvas together with an alpha mask and a feather weight (distance to the image border). (5) Blend: naive pasting is shown for reference; feathering takes the weighted average at every pixel; the 2-band blend feathers only the low frequencies and takes high frequencies from one image per pixel, which removes ghosting. If a flat mosaic of all images is impossible, the longest valid runs are used and the report says so.
